## ДОБАВЛЕННЫЕ ТРЕБОВАНИЯ

### Требование: Одностраничный интерфейс
Система ДОЛЖНА предоставлять одну страницу, на которой список точек расположен слева вертикальным столбцом, а координатная плоскость с графиком — справа.

#### Сценарий: Открытие приложения
- **КОГДА** пользователь открывает приложение
- **ТОГДА** он видит список точек и график одновременно без перехода между страницами

#### Сценарий: Узкий экран
- **КОГДА** ширины экрана недостаточно для удобного расположения двух колонок
- **ТОГДА** интерфейс сохраняет доступность списка и графика без горизонтальной прокрутки всей страницы

### Требование: Построение ломаной
Система ДОЛЖНА отображать все сохранённые точки на координатной плоскости и соединять соседние точки отрезками в порядке возрастания их `id`.

#### Сценарий: Несколько точек
- **КОГДА** загружено не менее двух точек
- **ТОГДА** график показывает каждую точку и соединяет последовательные точки отрезками

#### Сценарий: Одна точка
- **КОГДА** загружена одна точка
- **ТОГДА** график показывает точку без соединяющих отрезков

#### Сценарий: Пустой список
- **КОГДА** сохранённых точек нет
- **ТОГДА** график показывает пустое состояние без ошибки

### Требование: Немедленное обновление графика
Система ДОЛЖНА обновлять список и график сразу после каждого допустимого локального изменения координат или порядка, добавления либо удаления точки, не ожидая перезагрузки страницы. Состояние ДОЛЖНО быть согласовано с последним успешно подтверждённым ответом backend.

#### Сценарий: Изменение координаты
- **КОГДА** пользователь вводит допустимую координату
- **ТОГДА** соответствующая точка и соединённые с ней отрезки немедленно занимают новое положение

#### Сценарий: Изменение состава или порядка
- **КОГДА** пользователь добавляет, удаляет или перемещает точку
- **ТОГДА** список и ломаная немедленно отражают новый состав и порядок точек

#### Сценарий: Отказ backend
- **КОГДА** backend отклоняет изменение, уже показанное локально
- **ТОГДА** список и график возвращаются к последнему подтверждённому состоянию, а пользователь видит сообщение об ошибке
