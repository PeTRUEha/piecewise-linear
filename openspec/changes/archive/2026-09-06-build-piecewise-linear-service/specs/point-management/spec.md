## ДОБАВЛЕННЫЕ ТРЕБОВАНИЯ

### Требование: Хранение точек
Система ДОЛЖНА хранить каждую точку в PostgreSQL как три значения: целочисленный идентификатор `id`, координату абсциссы `x` и координату ординаты `y`. Координаты ДОЛЖНЫ быть конечными числовыми значениями.

#### Сценарий: Загрузка сохранённых точек
- **КОГДА** клиент запрашивает точки
- **ТОГДА** система возвращает все сохранённые точки с полями `id`, `x` и `y` в порядке возрастания `id`

#### Сценарий: Отклонение некорректных координат
- **КОГДА** клиент отправляет отсутствующее, нечисловое или бесконечное значение координаты
- **ТОГДА** система отклоняет изменение с ошибкой валидации и не изменяет сохранённые точки

### Требование: Добавление точки
Система ДОЛЖНА предоставлять на единственной странице кнопку добавления точки. Пользователь ДОЛЖЕН задавать координаты новой точки до её сохранения, а система ДОЛЖНА назначать ей идентификатор больше идентификаторов всех существующих точек.

#### Сценарий: Добавление первой точки
- **КОГДА** пользователь добавляет точку в пустой список и задаёт допустимые координаты
- **ТОГДА** система сохраняет точку и показывает её первой в списке

#### Сценарий: Добавление точки в существующий список
- **КОГДА** пользователь добавляет точку при наличии сохранённых точек
- **ТОГДА** система сохраняет новую точку в конце упорядоченного списка

### Требование: Редактирование координат
Система ДОЛЖНА позволять редактировать обе координаты каждой точки непосредственно в списке без отдельной перезагрузки страницы. Каждое завершённое допустимое изменение ДОЛЖНО автоматически сохраняться через API без отдельной кнопки сохранения.

#### Сценарий: Успешное редактирование
- **КОГДА** пользователь завершает ввод допустимого значения координаты точки
- **ТОГДА** интерфейс обновляет точку и система сохраняет новое значение в PostgreSQL

#### Сценарий: Ошибка сохранения изменения
- **КОГДА** backend не может сохранить изменённую координату
- **ТОГДА** интерфейс сообщает об ошибке и восстанавливает последнее подтверждённое сервером состояние

### Требование: Удаление точки
Система ДОЛЖНА предоставлять действие удаления для каждой точки и ДОЛЖНА удалять выбранную точку из PostgreSQL.

#### Сценарий: Успешное удаление
- **КОГДА** пользователь запускает удаление точки и подтверждает действие
- **ТОГДА** система удаляет точку и возвращает актуальный упорядоченный список

### Требование: Изменение порядка точек
Система ДОЛЖНА позволять изменять порядок точек только перетаскиванием (drag-and-drop). Кнопки перемещения вверх и вниз НЕ ДОЛЖНЫ отображаться. После изменения порядка система ДОЛЖНА в одной транзакции переписать идентификаторы всех точек последовательными значениями от `1` до количества точек согласно новому порядку.

#### Сценарий: Перетаскивание точки
- **КОГДА** пользователь перетаскивает точку на новую позицию между другими точками
- **ТОГДА** система сохраняет полный новый порядок и перенумеровывает все точки в соответствии с ним

#### Сценарий: Элементы управления порядком
- **КОГДА** пользователь просматривает список точек
- **ТОГДА** каждая точка доступна для перетаскивания, а кнопки перемещения вверх и вниз отсутствуют

#### Сценарий: Ошибка сохранения порядка
- **КОГДА** backend не может транзакционно сохранить полный новый порядок
- **ТОГДА** ни один идентификатор не изменяется, а интерфейс восстанавливает последнее подтверждённое сервером состояние и сообщает об ошибке

### Требование: Асинхронный API точек
Система ДОЛЖНА предоставлять под префиксом `/api/v1` асинхронный HTTP API для загрузки, создания, редактирования, удаления и полного переупорядочивания точек. Контракты API ДОЛЖНЫ быть опубликованы в `/docs` и `/openapi.json`.

#### Сценарий: Использование API интерфейсом
- **КОГДА** пользователь выполняет поддерживаемое действие с точками
- **ТОГДА** frontend выполняет соответствующий запрос API и применяет подтверждённое backend состояние без перезагрузки страницы

#### Сценарий: Просмотр контракта API
- **КОГДА** разработчик открывает `/docs` или `/openapi.json`
- **ТОГДА** система предоставляет актуальное описание всех публичных операций API
