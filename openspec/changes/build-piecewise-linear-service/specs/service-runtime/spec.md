## ДОБАВЛЕННЫЕ ТРЕБОВАНИЯ

### Требование: Локальный запуск в контейнерах
Система ДОЛЖНА запускаться локально через Docker Compose как согласованный набор frontend, асинхронного backend и PostgreSQL.

#### Сценарий: Запуск демонстрационной среды
- **КОГДА** разработчик выполняет документированную команду локального запуска с настроенным окружением
- **ТОГДА** Docker Compose запускает доступное в браузере приложение, backend и PostgreSQL

### Требование: Production-развёртывание
Система ДОЛЖНА разворачиваться через Docker Compose на одном Linux-сервере, где Nginx раздаёт собранный frontend и проксирует запросы `/api` в FastAPI.

#### Сценарий: Запуск production-среды
- **КОГДА** оператор запускает production-конфигурацию с обязательными переменными окружения
- **ТОГДА** приложение доступно через Nginx, а frontend обращается к backend по тому же источнику через `/api`

### Требование: Самодостаточные образы
Production-сервер ДОЛЖЕН требовать только Docker с поддержкой Compose и НЕ ДОЛЖЕН требовать установленного Python, `uv`, Node.js или npm.

#### Сценарий: Развёртывание на чистом сервере
- **КОГДА** на Linux-сервере установлены Docker и Compose, но отсутствуют языковые среды проекта
- **ТОГДА** оператор может собрать или запустить контейнерные образы и получить работоспособный сервис

### Требование: Управление проектом
Корень репозитория ДОЛЖЕН содержать Makefile с документированными командами установки, запуска, проверок, миграций, сборки и развёртывания.

#### Сценарий: Просмотр доступных команд
- **КОГДА** разработчик запрашивает справку Makefile
- **ТОГДА** он получает перечень поддерживаемых команд и их назначение

### Требование: Автоматизированное качество
Проект ДОЛЖЕН предусматривать Ruff, Pyright, pytest, coverage и pre-commit для backend, проверки frontend, интеграционные проверки с настоящим PostgreSQL, Playwright E2E полного пользовательского сценария, а также проверки Docker-образов и health endpoints.

#### Сценарий: Выполнение полного набора проверок
- **КОГДА** разработчик или CI запускает документированную полную проверку проекта после создания одобренных тестов
- **ТОГДА** выполняются статические проверки, тесты backend и frontend, интеграционные и E2E-сценарии и проверки контейнеров

### Требование: Независимость репозитория
Сервис ДОЛЖЕН содержать все необходимые для сборки, запуска и сопровождения файлы внутри собственного репозитория и НЕ ДОЛЖЕН зависеть от каталога `common` во время выполнения.

#### Сценарий: Клонирование отдельно от рабочей области
- **КОГДА** репозиторий клонирован без каталога `common`
- **ТОГДА** документированные операции сборки, проверки и запуска остаются доступными
